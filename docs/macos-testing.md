# Mac 验收

## 自动检查

运行 `bash scripts/test-mac.sh`：配置与播放状态测试、Shell 语法、Apple Silicon / Intel 通用编译、应用签名和预览模式只读检查。`--preview --check` 不要求安装 Codex；实际机器的 `--check` 才验证 Codex 查找。

运行 `bash scripts/package-mac.sh`：使用公开配置打包，验证签名并输出 ZIP 和 SHA-256。解压后应包含完整应用、视频、MIT 与媒体声明。

## 登录桌面上的检查

1. 已安装 Codex，运行 `--check`，确认找到的路径是正确客户端。
2. `--preview`：能播放随附视频与音轨，13 秒左右淡出并退出，客户端不会被启动。
3. 正常启动：视频窗口中央显示，真实 Codex 已打开时复用，动画结束后窗口撤下，客户端可以继续操作。
4. 冷启动：先保存工作并手动退出 Codex，再打开启动器；确认等待节点和客户端交接。
5. Esc：播放中按 Esc，窗口立即消失、声音停止，客户端继续启动并激活。
6. 临时配置副本设为不存在的 `appPath`：错误清晰，启动器退出后不留窗口。
7. 临时配置副本设为不存在或无法解码的 `video`：启动器仍交接到 Codex，不无限显示黑屏。
8. 小屏幕、外接屏幕、不同缩放、其他 Space 和全屏状态：窗口不超出当前屏幕可用区域。客户端 Space 切换由 macOS 管理。
9. 将应用复制到带空格的其他目录后运行；删除该副本时官方客户端和 Dock 原入口仍正常。

故障测试在临时应用副本中进行，改配置后重新 ad-hoc 签名。不能用纯逻辑测试替代真实播放和客户端交接。Intel 编译成功只证明产物含 x86_64，不代表 Intel 机器真机验证。

## 限制

没有实时客户端画面嵌入、客户端窗口对齐或全局启动入口替换。没有 Developer ID 签名、公证、后台服务或开机自启。系统启动完成标志不等于客户端所有数据就绪。窗口处于其他 Space / 全屏时，交接体验需在相应机器人工检查。
